# Plugy Engine

Небольшая CMS на PHP и SQLite. В комплекте главная страница студии «Пиксель» и журнал. В админке можно добавлять, редактировать, скрывать, переставлять и удалять блоки главной, а также сохранять черновики и публиковать статьи.

## Локальный запуск

Нужен PHP 8.3+ с расширением `pdo_sqlite`. На Windows включите `extension=pdo_sqlite` в активном `php.ini` и проверьте наличие модуля командой `php -m`.

Из корня проекта:

```shell
php -S 127.0.0.1:8080 -t public
```

Откройте [демо-сайт](http://127.0.0.1:8080/) или [админку](http://127.0.0.1:8080/admin/). Локальные логин и пароль по умолчанию — `admin` и `admin`. При первом открытии Plugy создаст `var/plugy.sqlite`, таблицы и стартовый контент. В разделе «Настройки» можно сразу сменить пароль.

## Запуск на сервере

1. Укажите `public/` как корень сайта для веб-сервера. Каталог `var/` должен быть доступен PHP для записи и находиться вне корня сайта.
2. Настройте HTTPS. Если TLS завершается перед PHP, настройте веб-сервер так, чтобы он передавал PHP параметр `HTTPS=on` для защищённых запросов. Доверяйте значению только из конфигурации веб-сервера.
3. Для новой базы задайте в окружении PHP переменную `PLUGY_ADMIN_PASSWORD` со случайным паролем длиной от 15 символов и до 72 байт. Откройте сайт, чтобы создать базу, затем удалите установочную переменную из окружения. Логин — `admin`. Если переносите локальную базу, сначала смените текущий пароль через админку при локальном запуске.

Встроенный сервер PHP предназначен для локальной разработки. Для резервного копирования используйте средства резервного копирования SQLite либо копируйте файл базы, когда приложение остановлено.

## Как устроено

- `public/` — точки входа и статические файлы. `app/` — логика, схема базы и шаблоны. `var/` — база и сессии.
- Для блоков доступны три типа: «Первый экран», «Текстовая секция» и «Акцентный блок». Текст статьи вводится обычным текстом с переносами строк. Адрес статьи можно указать вручную или оставить пустым для автогенерации.
- Пароль хранится в виде хеша Argon2id, при отсутствии поддержки используется bcrypt. Сессии хранятся на сервере, ID обновляется после входа и смены пароля. Формы защищены CSRF-токеном. Вход ограничен по IP и учётной записи, а смена пароля завершает остальные сессии.
