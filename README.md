# Plugy Engine

Небольшая CMS на PHP для MySQL и MariaDB. В комплекте демо-сайт студии с главной страницей и журналом. В админке можно добавлять, редактировать, скрывать, переставлять и удалять блоки главной, а также сохранять черновики и публиковать статьи.

## Локальный запуск

Нужен PHP 8.3+ с расширением `pdo_mysql` и запущенный MySQL или MariaDB. На Windows включите `extension=pdo_mysql` в активном `php.ini` и проверьте наличие модуля командой `php -m`. Создайте пустую базу и предоставьте пользователю доступ к ней.

Из корня проекта:

```shell
php -S 127.0.0.1:8080 -t admin/assets app/router.php
```

Откройте [сайт](http://127.0.0.1:8080/) или [админку](http://127.0.0.1:8080/admin/). Установщик запросит параметры базы, затем предложит задать пароль для логина `admin`.

## Установка на обычный PHP-хостинг

1. В панели хостинга включите PHP 8.3 или новее и `pdo_mysql`. Создайте пустую базу MySQL или MariaDB и назначьте ей пользователя с правами чтения, записи и создания таблиц.
2. Распакуйте подготовленный архив прямо в корневую папку домена, например `public_html/`. Файл `index.php` и папки `admin/`, `app/`, `site/` должны оказаться на одном уровне. Если домен показывает стандартную заглушку, переместите существующий `index.html` заглушки из папки сайта.
3. Откройте домен по HTTP или HTTPS. Введите название базы, имя пользователя, пароль и хост. Порт по умолчанию — `3306`.
4. После проверки подключения задайте пароль для логина `admin`. Plugy сохранит подключение, создаст таблицы, добавит демо-контент и откроет страницу входа.

Загружайте только файлы из подготовленного архива. Если вы уже загрузили старый `app.zip` и распаковали папку `var/`, переместите архив и папку за пределы корня сайта. В обоих могут быть данные и сессии предыдущей установки.

По умолчанию установка из архива создаёт отдельную папку `.plugy-…` рядом с корневой папкой сайта. В ней хранятся файл подключения и сессии. Если хостинг ограничивает запись в соседние папки, укажите в `app/install.local.php` параметр `data_directory` с абсолютным путём к закрытой папке, доступной PHP для записи. Например, `/home/account/plugy-data`.

Существующие установки на SQLite продолжают работать через `pdo_sqlite`. При переносе прежней установки укажите закрытую папку с файлом `plugy.sqlite`. Перед переносом базы с локальным паролем смените его в админке локального сайта.

На тестовых доменах можно работать по HTTP. На публичных сайтах HTTPS шифрует пароль и сессионную cookie при передаче. Если TLS завершается перед PHP, настройте веб-сервер так, чтобы для защищённых запросов PHP получал параметр `HTTPS=on`.

При установке **из исходников** укажите корневую папку проекта как корень веб-сервера. На публичном домене завершите установку сразу после загрузки файлов. До первого успешного запуска форма доступна посетителям сайта.

Встроенный сервер PHP предназначен для локальной разработки. Для резервного копирования используйте экспорт MySQL или MariaDB и сохраняйте копию файла подключения из закрытой папки данных.

## Обновление через GitHub Actions

Workflow `.github/workflows/deploy.yml` запускается при push в `main` или вручную через Actions. В Repository secrets должны быть настоящие значения `SFTP_HOST` (адрес SSH-сервера), `SFTP_USERNAME` (пользователь хостинга), `SFTP_PASSWORD` (пароль пользователя SFTP). На хостинге должен быть разрешён доступ по SFTP с паролем на порту 22. SSH-ключ не требуется. Пустые значения и тестовое значение `1` останавливают запуск.

Передача выполняется стандартным OpenSSH SFTP в пакетном режиме. Каждый запуск загружает все отслеживаемые файлы `admin/`, `app/`, `site/` и корневой `index.php`. Остальные файлы на сервере не удаляются. Локальная конфигурация, база, сессии и сохранённые в закрытой папке правки темы не входят в загрузку. Старые файлы предыдущей структуры автоматически не удаляются.

После передачи скрипт скачивает CSS и JavaScript редактора обратно по SFTP и с публичного домена и сравнивает их с файлами коммита. Ошибки подключения, передачи и несовпадение содержимого делают запуск красным. Путь хостинга и адрес проверяемого домена заданы в `REMOTE_PATH` и `SITE_URL` workflow. Первое SSH-подключение принимает ключ сервера автоматически (`accept-new`); для постоянной проверки его подлинности потребуется отдельно закрепить известный ключ хостинга.

## Редактор кода

В `site/` находятся настоящие PHP-шаблоны: `index.php` — каркас, `header.php` и `footer.php` — шапка и подвал, `home.php` — главная, `page.php` — страницы, `article.php` — статья. Повторно используемые части лежат в `site/components/`. CSS и JS остаются отдельными файлами.

Редактор кода показывает эти файлы с подсветкой PHP. Через «Новый компонент» можно создать свой компонент. Например, `component('banner', ['title' => 'Привет']);` подключает `components/banner.php`, где доступна переменная `$title`. `template('header', ['title' => 'Заголовок']);` подключает обычный шаблон. Пользуйтесь этими функциями для подключения частей темы, чтобы учитывались правки из админки.

Сохранённые версии находятся в закрытой папке `theme/` и имеют приоритет над исходниками `site/`; обновление приложения их не перезаписывает. Перед сохранением PHP проверяется синтаксис. Выполнение шаблона с ошибкой показывает страницу ошибки; админка продолжает работать и позволяет исправить код. PHP-шаблоны имеют доступ к серверу и предназначены для доверенного администратора.

## Поля и повторители

1. В разделе «Поля» создайте группу, выберите область: весь сайт, страницы или статьи. Для страниц и статей можно выбрать конкретную запись или все записи этого типа.
2. Добавьте поля с названием и уникальным ключом. Доступны текст, большой текст, изображение, ссылка, число, переключатель и повторитель.
3. У повторителя создайте поля строки. Строки можно добавлять, удалять и перемещать. Поддерживается один уровень повторения, до 50 строк; до 30 полей в группе или строке.
4. Значения общих полей заполняются в «Данные сайта». Остальные — в редакторе соответствующей страницы или статьи. Изображения можно загрузить (JPG, PNG, GIF, WebP до 5 МБ) или указать URL. Файлы хранятся в закрытой папке `media/` и отдаются через PHP.

```php
<?php
$title = get_field('hero_title');           // поле текущей страницы / статьи
$phone = get_field('phone', 'options');      // общее поле
$cover = get_field('cover', 'article:12');   // поле конкретной статьи
$about = get_field('subtitle', 'page:2');    // поле конкретной страницы
?>
<h1><?php field('hero_title'); ?></h1>
<img src="<?php field('cover'); ?>" alt="">

<?php foreach (get_field('benefits', 'options') as $row): ?>
    <h2><?= e($row['title']) ?></h2>
    <p><?= e($row['description']) ?></p>
<?php endforeach; ?>
```

`get_field()` возвращает исходное значение, число, boolean или массив строк. `field()` выводит скалярное значение с HTML-экранированием; `e()` экранирует значения внутри повторителя. Третий аргумент обеих функций — значение по умолчанию. Для определённого повторителя без строк возвращается `[]`. Общие поля выбираются явно через `options`, автоматического смешивания с полями записи нет. При переименовании ключа прежнее значение не переносится на новый ключ автоматически.

Группа «Сайт» с подписью подвала и повторителем преимуществ создаётся при обновлении. Она уже подключена к демо-шаблонам. Для других полей добавьте вызов в нужный PHP-шаблон — расположение определяете вы.

При первом открытии обновлённого сайта таблицы страниц и полей создаются автоматически в существующей БД. Статьи, блоки и аккаунт сохраняются. Главная доступна по `/`, новые страницы — `?page=адрес`. Старые HTML-шаблоны больше не исполняются; ранее сохранённые HTML-версии в закрытой папке не удаляются и могут служить источником для ручного переноса индивидуальной вёрстки в PHP. Сохранённые CSS и JS продолжают применяться.

Проверки: `php -d extension=pdo_sqlite tests/fields.php` (на системах, где расширение уже включено, достаточно `php tests/fields.php`).

## Как устроено

- `index.php` открывает сайт или установщик. В `admin/` находятся входная точка админки, её контроллер и ресурсы в `admin/assets/`, включая общий шрифт Inter. `site/` — клиентская часть сайта. `app/` — серверная логика, схема базы и PHP-шаблоны. При локальном запуске параметры подключения и сессии хранятся в `var/`.
- Для блоков доступны три типа: «Первый экран», «Текстовая секция» и «Акцентный блок». Текст статьи вводится обычным текстом с переносами строк. Адрес статьи можно указать вручную или оставить пустым для автогенерации.
- Пароль хранится в виде хеша Argon2id, при отсутствии поддержки используется bcrypt. Сессии хранятся на сервере, ID обновляется после входа и смены пароля. Формы защищены CSRF-токеном. Вход ограничен по IP и учётной записи, а смена пароля завершает остальные сессии.
